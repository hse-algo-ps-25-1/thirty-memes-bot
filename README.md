# thirty-memes-bot

Telegram-бот для семинара. Задание студентам — алгоритм на **закрытом словаре**: на любой входной текст вернуть ровно одно значение из фиксированного набора. Словарь — 30 мемов-картинок. Команда выбирает предметную область, собирает по ней 30 единиц и пишет правило выбора так, чтобы ответ бота был по возможности осмысленным: не случайная карта и не новый текст, а один файл из своего набора.

В репозитории одновременно лежат несколько таких реализаций (папки в `algorithms/`). Бот в каждый момент отвечает одной из них; преподаватель переключает активную папку, не перезапускавая процесс.

Ниже — установка и запуск на своей машине. Команды даны для Linux (bash) и Windows (PowerShell). Их нужно вводить по очереди, не копировать весь блок сразу, если шаг просит что-то проверить или отредактировать файл.

## Что должно быть заранее

- Аккаунт в Telegram.
- Git (проверка: `git --version`). Если команды нет — поставьте Git с [git-scm.com](https://git-scm.com/) и откройте терминал заново.
- Доступ к репозиторию: адрес выдаёт преподаватель.

Интерпретатор Python 3.14 ставить отдельно не обязательно: его поставит `uv` (шаг 2).

`uv` — программа, которая создаёт виртуальное окружение проекта, ставит зависимости из `pyproject.toml` и запускает код командой `uv run`. Активировать `.venv` вручную не нужно.

## 1. Установить `uv`

**Linux**

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Закройте терминал и откройте его снова (или выполните команду, которую установщик напечатает про `PATH`). Проверка:

```bash
uv --version
```

**Windows (PowerShell)**

```powershell
irm https://astral.sh/uv/install.ps1 | iex
```

Закройте PowerShell и откройте снова. Проверка:

```powershell
uv --version
```

Если PowerShell запрещает скрипты, один раз для текущего окна:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

затем повторите установку `uv`.

## 2. Установить Python 3.14 через `uv`

В корне проекта указано `.python-version` со строкой `3.14`. Команда ставит именно этот выпуск, если его ещё нет на машине.

**Linux и Windows**

```bash
uv python install 3.14
```

Проверка:

```bash
uv python list
```

В списке должна быть строка с 3.14.

## 3. Склонировать репозиторий и перейти в него

Подставьте адрес, который выдал преподаватель.

**Linux**

```bash
git clone <адрес-репозитория>
cd thirty-memes-bot
```

**Windows**

```powershell
git clone <адрес-репозитория>
cd thirty-memes-bot
```

Дальше все команды выполняются **из корня** `thirty-memes-bot` (в нём лежат `pyproject.toml` и каталог `algorithms`).

## 4. Собрать окружение проекта

**Linux и Windows**

```bash
uv sync
```

Команда создаст каталог `.venv`, поставит пакеты и сам проект. Каталог `.venv` в git не входит: его нельзя коммитить и не нужно копировать с другой машины — на каждой системе запускают свой `uv sync`.

Если `uv sync` ругается на версию Python, вернитесь к шагу 2.

## 5. Настроить переменные окружения

Секреты читаются из файла `.env` в корне репозитория. Образец — `.env.example`. Сам `.env` в git не попадает.

**Linux**

```bash
cp .env.example .env
```

**Windows**

```powershell
Copy-Item .env.example .env
```

Откройте `.env` в редакторе и заполните две строки.

### Токен бота

1. В Telegram откройте [@BotFather](https://t.me/BotFather).
2. Отправьте `/newbot` и следуйте вопросам (имя и username бота).
3. BotFather пришлёт токен вида `123456789:AAH...`. Это секрет: его нельзя публиковать в чате курса, в pull request и в `README`.
4. В `.env` замените пустое значение:

```env
TELEGRAM_BOT_TOKEN=123456789:AAH-вставьте-свой-токен
```

Пробелов вокруг `=` и кавычек вокруг токена быть не должно.

Если бот уже создан, токен можно заново запросить у BotFather командой `/token`.

### Числовой идентификатор преподавателя

Команды `/teams`, `/who` и `/use` принимает только тот, чей Telegram `user_id` перечислен в `ADMIN_USER_IDS`. Это число, не username.

1. Напишите любому боту, который показывает id, например [@userinfobot](https://t.me/userinfobot).
2. Скопируйте число (только цифры).
3. В `.env` укажите его **в квадратных скобках** — это список JSON, даже если id один:

```env
ADMIN_USER_IDS=[11111111]
```

Несколько преподавателей:

```env
ADMIN_USER_IDS=[11111111, 22222222]
```

Итоговый `.env` выглядит так (значения свои):

```env
TELEGRAM_BOT_TOKEN=123456789:AAH-вставьте-свой-токен
ADMIN_USER_IDS=[11111111]
```

Пустой токен или пустой список админов: процесс бота не запустится или сразу завершится с ошибкой валидации.

## 6. Запустить бота

**Linux и Windows**

```bash
uv run thirty-memes-bot
```

Терминал должен остаться открытым: идёт long polling. Остановка — `Ctrl+C`.

В Telegram найдите своего бота по username, которого вы задали в BotFather, нажмите Start и отправьте любой текст. Должна прийти картинка из `algorithms/demo/memes/` и подпись с именем файла.

Команды `/teams`, `/who`, `/use demo` сработают только из аккаунта, чей id указан в `ADMIN_USER_IDS`. С другого аккаунта бот ответит, что команда доступна только преподавателю.

Если процесс сразу падает с сообщением про `TELEGRAM_BOT_TOKEN` или `.env` — проверьте шаг 5: файл лежит в корне `thirty-memes-bot`, имена переменных как в образце, нет лишних кавычек.

Если бот молчит в Telegram: процесс в терминале ещё запущен; токен скопирован целиком; вы пишете именно тому боту, чей токен в `.env`.

## 7. Локальный диалог без Telegram

Так проверяют алгоритм, не поднимая бота и не тратя токен.

**Linux и Windows**

```bash
uv run local-chat demo
```

Аргумент `demo` — имя папки в `algorithms/`. Ввод строки, вывод имени файла, выход — `выход` или `exit`. Ход диалога дописывается в `dialog_log.txt` в текущем каталоге (этот файл тоже не коммитят).

## 8. Запустить тесты

Команды выполняются из корня `thirty-memes-bot`. Отдельной команды `uv test` нет: `uv run` запускает обычный `unittest` в окружении проекта.

Тесты оболочки (сессии, список папок, загрузка модуля):

**Linux и Windows**

```bash
uv run python -m unittest discover -s tests -v
```

Флаг `-v` печатает имя каждого теста.

Тесты демо-алгоритма лежат в его папке и импортируют локальный `algorithm.py`. Их запускают так:

```bash
uv run python algorithms/demo/test.py
```

На Linux и Windows команда одна и та же. Если `uv` не находится, вернитесь к шагу 1; если нет `.venv` — к шагу 4 (`uv sync`).

## 9. Запустить в Docker

Альтернатива шагам 1–4 и 6: Python, пакеты и код собираются в образ. На машине нужны Docker (Engine или Desktop) и заполненный `.env` из шага 5. Токен в образ не копируется.

Проверка, что клиент отвечает:

```bash
docker version
```

Команды ниже — из корня `thirty-memes-bot`.

Собрать образ (первый раз скачивает базовый образ и словарь pymorphy, это может занять несколько минут):

**Linux и Windows**

```bash
docker build -t thirty-memes-bot .
```

Запустить бота. `--env-file` подставляет переменные из локального `.env`; `--rm` удаляет контейнер после остановки; `--init` корректно обрабатывает `Ctrl+C`.

**Linux и Windows**

```bash
docker run --rm --init --env-file .env thirty-memes-bot
```

Терминал оставьте открытым, как при `uv run thirty-memes-bot`. Остановка — `Ctrl+C`. В Telegram проверка та же, что в шаге 6.

Если сразу падает с ошибкой про `TELEGRAM_BOT_TOKEN` или `ADMIN_USER_IDS` — файл `.env` лежит в текущем каталоге и заполнен, как в шаге 5. Сборка образ без токена проходит, без `.env` не запускается только контейнер.

Чтобы править папки в `algorithms/` без пересборки, примонтируйте каталог с хоста. Тогда `/use` видит новые команды сразу после появления папки на диске.

**Linux**

```bash
docker run --rm --init --env-file .env -v "$(pwd)/algorithms:/app/algorithms" thirty-memes-bot
```

**Windows (PowerShell)**

```powershell
docker run --rm --init --env-file .env -v "${PWD}/algorithms:/app/algorithms" thirty-memes-bot
```

Пересоберите образ (`docker build …`), если меняли оболочку в `src/`, `pyproject.toml` или `uv.lock`. Смена только файлов в смонтированном `algorithms/` пересборки не требует.

## Команды преподавателя

Только `user_id` из `ADMIN_USER_IDS`.

- `/teams` — папки в `algorithms/`
- `/who` — какая реализация активна
- `/use <имя>` — включить папку и сбросить окна истории у всех

Остальным бот отвечает на обычный текст картинкой из активного модуля.

## Структура

Оболочка — пакет `src/thirty_memes_bot`. Реализации — `algorithms/<имя>/` с файлами `algorithm.py`, `features.txt` и каталогом `memes/`. Первая версия содержит только `demo`. Образ контейнера — `Dockerfile` в корне. Конвейер — `.github/workflows/ci.yml`.

Текст перед выбором мема можно привести к стандартному виду общей функцией `from thirty_memes_bot.text import normalize`: нарезка на слова и леммы (падежи и окончания не плодят разные ключи). Демо так и делает. Признаки в `features.txt` нужно хранить в тех же формах, иначе чат и словарь снова разъедутся. Своё правило нарезки объявляют на защите.
